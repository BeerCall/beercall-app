# Recette E2E de release 11c — raccordement CI et correspondance des scénarios

Date : 2026-11-13
Portée : `beercall-app`, PR #10 (`0ebee88`, puis SHA réépinglé après publication frontend).

## Décision

La porte `E2E browser (Chromium)` exécute désormais la **recette courante de 39 scénarios**
(`beercall-frontend/tests/fluidite`, hors `world-probe.spec.ts`) sur une stack Docker
**jetable** construite depuis les gitlinks épinglés, avec bootstrap synthétique
(`scripts/seed_fluidite_demo.py`). Le job exige en plus **≥ 75 % de lignes couvertes par
les seuls E2E**, côté frontend et côté backend, sur le périmètre de mesure existant.

Le harnais est `scripts/run_release_e2e.py`. Il refuse de démarrer si la recette ne
contient plus exactement 39 scénarios (`lock_recipe`), si le port n'est pas libre, ou si
le répertoire de sortie existe déjà : aucune couverture périmée n'est réutilisée.

## Build instrumenté de la recette

Le build frontend de la stack jetable reçoit deux instrumentations distinctes :

- `VITE_E2E_COVERAGE=1` pour la collecte Istanbul par scénario ;
- `VITE_WORLD_PROBE=1` **en argument de build** (le `Dockerfile` réexporte cet
  `ARG` via `ENV`, un `ENV` injecté serait écrasé par la valeur vide par défaut).
  Il fournit la cible du levier de la machine à sous utilisée par `world-slot`.

Le panneau de performance (`VITE_FF_PERF_PANEL`) n'est **pas** activé : il n'est
requis par aucun des 39 scénarios et son instrumentation supplémentaire change
le profil de contexte WebGL observé par `worlds.spec`.

Les scénarios qui créent leur propre apéro actif ou programmé mettent de côté
l'apéro actif de référence du seed, puis le restaurent à l'identique. Les
assertions et les seuils métier restent inchangés.

## Garde de couverture

`scripts/run_release_e2e.py` :

- instrumente le build frontend (`VITE_E2E_COVERAGE=1`) et collecte `window.__coverage__`
  par scénario ;
- exécute API et workers sous `coverage` (`.coveragerc` versionné : `api, core, db,
  models, services, workers, main`) ;
- combine uniquement les données de la stack jetable ;
- exige `covered * 100 >= 75 * total` en lignes, frontend et backend, sur les fractions
  brutes (pas d'arrondi complaisant) ;
- n'ajoute aucune exclusion et ne modifie pas les scripts de rapport existants
  (`coverage-report.mjs`, `backend-coverage-report.mjs`).

## Mesure fraîche du 2026-11-13

Recette exécutée sur une stack jetable neuve, pins `ccfbb4d` / `4399f83` plus
les corrections de bootstrap décrites ci-dessus :

- **39/39 scénarios verts** en 13,1 min ;
- **frontend 77,58 %** de lignes (4 246 / 5 473) ;
- **backend 75,33 %** de lignes (2 522 / 3 348).

## Limites

- La couverture E2E ne remplace pas les tests unitaires : elle borne le périmètre de
  parcours réellement exécuté, pas la couverture de chaque branche interne.
- Le retrait des tests unitaires redondants reste hors de ce raccordement ; il exige une
  preuve de remplacement, conformément au plan.
- La recette suppose le bootstrap synthétique du dépôt backend et ne touche ni la base de
  recette personnelle ni la production.
